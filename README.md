# План внедрения информационной системы

Веб-приложение для ведения **плана внедрения информационной системы**, сделанное по таблице
`Шаблон_плана_внедрения.xlsx`. Все данные из таблицы (паспорт системы, 10 этапов внедрения GLPI,
критерии готовности и приёмки, план возврата, реестр рисков, лист самопроверки) уже перенесены
в приложение — открыл и работаешь.

Приложение — это **один файл `index.html`**. Ничего не нужно устанавливать: ни сервер, ни базу данных,
ни Python/Node.js. Работает в любом современном браузере (Chrome, Edge, Firefox, Яндекс.Браузер, Safari)
на компьютере и на телефоне.

🌐 **Онлайн-версия:** https://keiltg.github.io/plan-vnedreniya/

## Описание вкладок

### 1. Обзор
Главная страница — сводка по проекту:
- **Выполнено этапов** — сколько этапов в статусе «Выполнен» и полоса прогресса;
- **До запуска** — сколько дней осталось до даты планируемого запуска;
- **Просрочено этапов** — этапы, у которых срок прошёл, а статус не «Выполнен»;
- **Высоких рисков** — риски с уровнем «Высокий» (6–9 баллов);
- **Готовность к запуску** — сколько критериев готовности отмечено;
- **Ближайшие этапы** — 5 невыполненных этапов с самыми ранними сроками;
- **Проблемы плана** — список всех найденных ошибок (просрочки, нарушения зависимостей, пустые поля);
- **Паспорт системы** — краткая карточка из листа «План внедрения».

### 2. План внедрения
Соответствует верхней части листа «План внедрения» в Excel.

**Паспорт системы** — 8 полей: название системы, назначение, целевые пользователи, цель внедрения,
что входит/не входит в работы, ограничения, дата планируемого запуска.

**Этапы внедрения** — таблица со столбцами:

| Столбец | Что писать |
|---|---|
| № | Ставится автоматически |
| Этап | Короткое название этапа |
| Содержание работ | Что конкретно делается |
| Ответственный | Должность или ФИО |
| Срок | Дата окончания этапа (выбирается в календаре) |
| Зависит от | Номера этапов через запятую: `7, 8`. Если зависимостей нет — `—` |
| Ожидаемый результат | Чем заканчивается этап (проверяемый результат) |
| Подтверждающий документ | Чем подтверждается результат (акт, отчёт, скриншот…) |
| Статус | Не начат / В работе / Выполнен |

Справа у каждой строки кнопки: **↑ ↓** — переместить, **✕** — удалить.
При перемещении или удалении этапа номера в столбце «Зависит от» у других этапов **автоматически пересчитываются**.

Если с этапом что-то не так, под статусом появляется красная подсказка ⚠ (наведите мышь — увидите все ошибки).

### 3. Диаграмма Ганта
Наглядный график всех этапов на шкале времени. Цвета полос:
- синий — не начат;
- оранжевый — в работе;
- зелёный — выполнен;
- красный — просрочен.

Красная вертикальная линия — сегодняшний день. Наведите мышь на полосу, чтобы увидеть даты и ответственного.

### 4. Запуск и возврат
Соответствует нижней части листа «План внедрения»:
- **Критерии готовности к запуску** — чек-лист, отмечайте галочкой выполненные пункты;
- **Критерии успешной приёмки** — чек-лист после запуска;
- **План возврата** — что делать, если запуск неудачный: условие, кто решает, что восстанавливаем,
  источник копии, допустимое время, проверка после возврата.

Кнопка **+** добавляет новый критерий, **✕** — удаляет.

### 5. Риски
Соответствует листу «Риски».
- **Реестр рисков**: риск, вероятность (Низкая/Средняя/Высокая), влияние (Низкое/Среднее/Высокое),
  предупреждающее действие, действие при наступлении. Уровень риска считается сам.
- **Матрица рисков** 3×3: в каждой клетке — номера рисков. Зелёная зона — низкий риск, жёлтая — средний,
  красная — высокий.

### 6. Проверка
Соответствует листу «Проверка».
- **Критерий** — что проверяем;
- **Автопроверка** — приложение само проверяет план и показывает ✓ OK или ✕ Нет с пояснением;
- **Самопроверка** — ваша оценка (Да / Нет / Частично);
- **Проверка другой пары** — оценка проверяющих;
- **Комментарий** — пояснения.

Если вы поставили «Да», а автопроверка нашла проблему, появится предупреждение
«Не совпадает с автопроверкой».

Ниже — **Замечания** и **Решения по замечаниям** (сколько угодно, кнопка «+ Замечание»).

## Где хранятся данные

Данные хранятся **в браузере** (`localStorage`) на том компьютере, где вы работаете.
Это значит:
- закрыли вкладку, выключили компьютер — данные остались;
- **на другом компьютере или в другом браузере данных не будет** — перенесите их через файл
  (Excel или JSON, см. ниже);
- в режиме «Инкогнито» данные удаляются после закрытия окна;
- если очистить данные сайтов в браузере — план сбросится к исходному шаблону.

> 💡 Совет: время от времени нажимайте **«Сохранить JSON»** или **«Сохранить в Excel»**,
> чтобы иметь копию в файле.

Кнопка **«Сброс»** возвращает исходные данные из шаблона (спросит подтверждение).

## Работа с Excel

### Сохранить в Excel
Кнопка **«Сохранить в Excel»** скачивает файл `План_внедрения_ГГГГ-ММ-ДД.xlsx` с тремя листами,
в той же раскладке, что и исходный шаблон:
1. **План внедрения** — паспорт, этапы (+ столбец «Статус»), критерии и план возврата;
2. **Риски** — реестр рисков (+ столбец «Уровень»);
3. **Проверка** — лист самопроверки и замечания.

Выполненные критерии готовности/приёмки помечаются знаком `✓` в конце текста.

### Открыть Excel
Кнопка **«Открыть Excel»** загружает таблицу, оформленную **по шаблону** (например, исходный
`Копия Шаблон_плана_внедрения.xlsx` или файл, ранее сохранённый из приложения).

Что ищет приложение при загрузке:
- на листе со словом «План» в названии:
  - подписи паспорта в столбце A (`Название системы`, `Назначение`, … `Дата планируемого запуска`), значение — в столбце B;
  - строку-заголовок, где A = `№`, B = `Этап`; ниже — этапы (столбцы A–I);
  - строку `Критерии готовности к запуску`; ниже — критерии готовности (столбец B),
    критерии приёмки (столбец E), план возврата (подписи в G, значения в H);
- на листе со словом «Риск» — строку-заголовок `№ | Риск | …` и риски под ней;
- на листе со словом «Провер» — строку `Критерий | …`, критерии под ней и строки `Замечание N` / `Решение по замечанию N`.

Даты понимаются в форматах `05.10.2026`, `2026-10-05` и как настоящие даты Excel.

> ⚠️ Загрузка Excel **заменяет** текущие данные в приложении. Если они нужны — сначала сохраните копию.

## Автоматические проверки плана

Приложение постоянно проверяет план и показывает ошибки во вкладке «Обзор → Проблемы плана»,
под статусом этапа и в листе «Проверка».

**Проверки этапов:**
- не указано название, ответственный, срок или результат;
- в «Зависит от» указан несуществующий этап или этап зависит сам от себя;
- срок этапа **раньше**, чем срок этапа, от которого он зависит;
- этап «В работе»/«Выполнен», а этап, от которого он зависит, ещё не выполнен;
- циклическая зависимость (1 → 2 → 1);
- этап заканчивается позже даты запуска;
- срок прошёл, а этап не выполнен (просрочен).

**Автопроверка листа «Проверка»:**

| Критерий | Как проверяется |
|---|---|
| Цель измерима | В тексте цели есть число (например, «2 рабочих дня», «90%») |
| Границы определены | Заполнены «Что входит» и «Что не входит» в работы |
| Не менее 7 этапов | Количество этапов ≥ 7 |
| Этапы расположены логично | Каждый этап зависит только от предыдущих по номеру, нет циклов |
| Указаны ответственные | У всех этапов заполнен ответственный |
| Сроки реалистичны | У всех этапов есть срок, и все сроки не позже даты запуска |
| Зависимости не нарушены | Нет ссылок на несуществующие этапы и сроков раньше зависимостей |
| Результаты проверяемы | У всех этапов есть ожидаемый результат и подтверждающий документ |
| Не менее 5 рисков | В реестре ≥ 5 заполненных рисков |
| Есть план возврата | Заполнены все 6 полей плана возврата |
| Определены критерии приёмки | Есть хотя бы один критерий приёмки |

Если переименовать критерий или добавить свой, автопроверка для него показывает «—».

## Как считаются риски

Каждой градации присваивается балл:

| Вероятность | Балл | | Влияние | Балл |
|---|---|---|---|---|
| Низкая | 1 | | Низкое | 1 |
| Средняя | 2 | | Среднее | 2 |
| Высокая | 3 | | Высокое | 3 |

**Уровень = вероятность × влияние** (от 1 до 9):
- 1–2 — 🟢 низкий;
- 3–4 — 🟡 средний;
- 6–9 — 🔴 высокий.

Пример: «Сбой сервера» — вероятность Средняя (2) × влияние Высокое (3) = **6 → высокий**.

## Как строится диаграмма Ганта

В шаблоне у этапов есть только **срок окончания**, поэтому начало вычисляется:
- **начало этапа** = самый поздний срок среди этапов, от которых он зависит;
- если зависимостей нет (первый этап) — за 7 дней до его срока;
- **конец этапа** = его срок.

Например, «Пробная эксплуатация» зависит от этапов 7 (13.11) и 8 (16.11), поэтому начинается 16.11
и заканчивается 27.11.

## Как использовать для другой системы

Приложение не привязано к GLPI. Чтобы вести план для другой системы:

**Способ 1 — через интерфейс:** просто перепишите паспорт, этапы, риски и т.д. прямо на странице.

**Способ 2 — через Excel:** заполните свой файл по шаблону и нажмите «Открыть Excel».

**Способ 3 — поменять данные по умолчанию в коде:** откройте `index.html` в любом текстовом редакторе
(Блокнот, VS Code), найдите блок `const DEFAULT_DATA = {` и замените значения. Именно эти данные
показываются при первом открытии и после кнопки «Сброс».

```js
const DEFAULT_DATA = {
  passport: {
    name: "GLPI — система учёта заявок в IT-отдел колледжа",
    ...
    launch: "2026-12-01"          // дата в формате ГГГГ-ММ-ДД
  },
  stages: [
    {title:"Обследование", content:"...", owner:"...", due:"2026-10-05",
     deps:"—", result:"...", doc:"...", status:"todo"},   // todo | progress | done
    ...
  ],
  ...
};
```

> Если вы уже открывали приложение в этом браузере, после изменения `DEFAULT_DATA` нажмите «Сброс»,
> иначе будут показаны ранее сохранённые данные.

## Структура проекта и устройство кода

```
plan-vnedreniya/
├── index.html                              — всё приложение (HTML + CSS + JavaScript)
├── Копия Шаблон_плана_внедрения.xlsx       — исходная таблица, по которой сделано приложение
└── README.md                               — эта инструкция
```

Внутри `index.html`:

| Часть | Что делает |
|---|---|
| `<style>` | Оформление, светлая/тёмная тема (CSS-переменные в `:root`), адаптивная вёрстка, стили печати |
| Разметка `<section>` | Шесть вкладок: `dash`, `plan`, `gantt`, `launch`, `risks`, `check` |
| `DEFAULT_DATA` | Данные из исходной Excel-таблицы |
| `load()` / `save()` / `normalize()` | Чтение и запись в `localStorage`, восстановление недостающих полей |
| `analyze()` | Поиск ошибок в этапах: зависимости, сроки, циклы (обход в глубину), просрочки |
| `autoCheck()` | Правила автопроверки для листа «Проверка» |
| `riskScore()` / `riskLevel()` | Расчёт уровня риска |
| `render*()` | Отрисовка каждой вкладки |
| `onEdit()` | Единый обработчик изменений всех полей (делегирование событий) |
| `moveStage()` / `removeStage()` / `remapDeps()` | Перемещение и удаление этапов с пересчётом зависимостей |
| `loadXLSX()` | Ленивая загрузка библиотеки [SheetJS](https://sheetjs.com/) 0.18.5 с cdnjs |
| `parseWorkbook()` | Разбор Excel-файла по шаблону |

Технологии: чистый HTML, CSS и JavaScript без фреймворков и сборки.
Единственная внешняя библиотека — SheetJS (только для Excel, загружается по требованию).

## Частые вопросы и решение проблем

**Кнопки Excel выдают «Нет доступа к интернету».**
Библиотека Excel загружается из интернета. Подключитесь к сети или используйте «Сохранить/Открыть JSON» —
они работают офлайн.

**Открыл на другом компьютере — данных нет.**
Данные хранятся в браузере. Перенесите их: на старом компьютере «Сохранить JSON», на новом — «Открыть JSON».

**Все этапы красные (просрочены).**
Срок этапа прошёл, а статус не «Выполнен». Поставьте статус «Выполнен» у завершённых этапов
или перенесите сроки.

**Загрузил свой Excel, а этапы не появились.**
Проверьте, что на листе плана есть строка-заголовок, где в столбце A написано `№`, а в столбце B — `Этап`,
и что название этапа находится в столбце B. Для паспорта подписи в столбце A должны совпадать с шаблоном.

**Хочу начать с чистого листа.**
Удалите этапы/риски кнопками ✕ и очистите поля — либо измените `DEFAULT_DATA` в коде и нажмите «Сброс».

**Изменения пропали после очистки браузера / режима инкогнито.**
Так работает `localStorage`. Регулярно делайте резервную копию в JSON или Excel.
